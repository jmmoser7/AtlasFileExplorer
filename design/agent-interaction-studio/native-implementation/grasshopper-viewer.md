# Grasshopper in Slate’s 3D viewer

The user confirmed the interaction choices on 12 November 2026. The scope below governs the native viewer and the release checks.

| Interaction | Required behavior |
|---|---|
| Open | Opening or placing a linked `.gh` or `.ghx` definition uses the existing 3D viewer. Slate runs the definition through its headless Rhino integration. |
| Preview | Show every component's visible preview, including curves, points, and shaded geometry. Respect the definition's preview visibility. Keep the last successful preview available during recomputation. |
| Controls | A Grasshopper squircle in the viewer’s shared toolbar opens a single panel containing the action and input capsules. The panel floats beneath the squircle toolbar on small viewers and uses the attached apron on large viewers. Keep the control label and value on one row. Numeric controls share Fillet’s rail and editable value chip; toggles use Slate’s segmented control. List choices open under their row. A color swatch opens Slate’s native color picker with a Back capsule to return to the controls. Discover every named control. Other named controls remain visible with their type and a hover explanation. |
| Solve | Update the preview live while dragging. Debounce input, keep only the newest pending values per viewer, and fence every result by the viewer, source revision, and solve generation. |
| Progress | Use the image generator’s on-card spinner, elapsed time, and busy outline for startup, live solve, authoring, and Bake. Keep progress visible with the palette closed. During authoring, show the latest public activity and provider-reported token usage when available. |
| Save | Persist input overrides per viewer in the workbook, keyed by the definition's stable control identities. Keep the linked definition unchanged. Coalesce a slider drag into one undo step. |
| Agent | Keep Agent beside Grasshopper Inputs in the 3D toolbar. Codex works in a dedicated folder from a copy of the linked `.gh` or `.ghx` and returns an editable `.ghx` revision to the viewer’s result history. Prefer an embedded C# component for modeling logic unless the user requests another approach. Expose named Grasshopper sliders and color controls on the definition so they remain editable in Slate. For a parametric chair, expose Seat height, Back height, Chair width, and Chair color. Keep the C# inside the Grasshopper definition that the viewer references. Choose a revision and select **Run definition** to switch the viewer to it. The original stays on disk. |
| Packages | On definition open, compare required libraries with the installed component catalog. Restore compatible missing packages automatically through Rhino's configured Package Manager sources. Retain installed user versions and show unresolved or incompatible requirements in the viewer. |
| Local plug-ins | When Package Manager cannot restore a requirement, drop a `.gha` or `.yak` onto the blocked viewer or its open Grasshopper palette. Check the missing component or library identity and retry the definition. Slate remembers verified `.gha` paths for the current user and checks the file hash before reuse. `.yak` archives use Rhino Package Manager's local install path. |
| Bake | The Grasshopper dropdown includes Bake. Write the visible preview geometry to a new `.3dm` and retain available layer and material attributes. Use the active solved revision so the file matches the result being baked. |
| Stack | Place the first baked 3D card beside the source viewer. Put each later bake below the previous one in world space. Each is an independent linked model artifact and one undoable placement. |

The viewport retains Slate’s existing 3D navigation, display, measurement, capture, selection, and canvas scaling. The dropdown uses the shared squircle and submenu owners, including their outside-click, Escape, and reopen behavior. During zoom or pan, the palette, toolbar, and node use the same camera transform on the same frame. Overlay icons use the standard icon stroke without a second outline. Solve and package progress belong in the existing node-local feedback. The ordinary model viewer continues to open its other supported formats through its current readers.

## Runtime and ownership

- The headless host owns archive reading, component visibility, input discovery, and actual Grasshopper solves. Keep a warm, serialized STA solve path for live edits. Stage preview data through the existing native model viewer and keep Grasshopper's internal document out of the workbook model.
- The workbook owns typed overrides and bake provenance. Stable instance IDs distinguish duplicate labels. A choice override refers to an existing item in the definition. The control catalog reports the current value, supported edits, and source range or options.
- Package restore runs off the canvas thread. Match missing library identity and version through Rhino’s Package Manager. Reopen the Slate-owned runtime when a newly installed library requires it, then verify that required components load. Show the actual package error if restore fails. [McNeel Package Restore](https://developer.rhino3d.com/en/guides/yak/package-restore-in-grasshopper/)
- The bake uses Grasshopper’s bake-aware SDK methods where available. Verify preview-only components separately so the displayed geometry and the baked output are both accounted for. Use a fresh headless document, validate the saved file, and publish through the existing linked-artifact and journal owners. [Grasshopper preview API](https://developer.rhino3d.com/api/grasshopper/html/M_Grasshopper_Kernel_GH_Component_DrawViewportMeshes.htm), [Grasshopper bake API](https://developer.rhino3d.com/api/gh1/type/grasshopper.kernel.igh-bakeawareobject/)

## Linking Grasshopper definitions

| Interaction | Required behavior |
|---|---|
| Port discovery | Grasshopper’s enabled Context Get components declare inputs. Context Bake and Context Print parameters declare outputs. Also recognize Rhino Compute’s legacy `RH_IN` and `RH_OUT` groups. Detect these across the definition regardless of their position. Order each side top to bottom as in Grasshopper. Keep port identities by instance GUID so changing a label or saving the definition leaves valid wires connected. An ordinary definition without markers keeps its existing viewer and controls. |
| Input values | Enter a number or text at the corresponding input, or wire a compatible Grasshopper output to it. Disconnected inputs use their Grasshopper defaults unless given a local value. Keep independent viewers of one file independent. |
| Grips | Place Grasshopper inputs on the left and outputs on the right. Start at the existing top grip datum. Use the standard muted Slate wire color for grips and cables. Place any Agent grips beneath the Grasshopper grips on their respective side. The Grasshopper controls palette and Agent toolbar retain their current roles. |
| Wire styles | A value in one branch uses a single stroke, multiple values in one branch use two solid strokes, and multiple branches use two dashed strokes. Read branch count and item count from the last completed output. Do not transform the payload based on its display. |
| Bundle | The input or output group context menu toggles **Bundle wires** and **Unbundle wires**. Multiple links between the same endpoints’ frames share a thicker muted trunk with individual leads. Links to other destinations remain separately traceable. This is a reversible display choice and does not change links or computation. |
| Solve | Run the affected downstream graph from a coherent set of inputs. A receiver waits for all affected upstream outputs before starting and keeps its last good preview while waiting. Display progress while waiting or solving, including when the palette is closed. Discard a stale completion after a control, source, or wire changes. Never trigger a cycle. |
| Refresh | Recheck the linked file on opening and when a source is saved, including an atomic file replacement. Coalesce rapid save events. On a stable new revision, recatalog the ports, keep valid links by identity, and solve affected viewers. Preserve the last good preview through a transient missing file or partial write. Surface incompatible or missing ports before accepting new data. |

McNeel’s Hops contract uses named contextual parameters, treats Tree Access as overriding list limits, and waits for all asynchronous results before downstream execution. Slate uses this as its boundary contract. Grasshopper retains branch paths, matching, grafting, flattening, and script-level data access. [Hops components](https://developer.rhino3d.com/en/guides/compute/hops-component/), [Grasshopper data structures and wire styles](https://developer.rhino3d.com/en/guides/grasshopper/gh-algorithms-and-data-structures/data-structures/)

Grasshopper expires downstream objects when an input changes. Its scheduler defers a requested solve until a running solve finishes. Slate applies the same ordering across linked definitions while keeping its canvas separate from the solver. McNeel Compute also watches linked files to invalidate cached definitions. [ExpireSolution](https://developer.rhino3d.com/api/grasshopper/html/M_Grasshopper_Kernel_GH_DocumentObject_ExpireSolution.htm), [ScheduleSolution](https://developer.rhino3d.com/api/grasshopper/html/Overload_Grasshopper_Kernel_GH_Document_ScheduleSolution.htm), [Rhino 8 Compute definition loader](https://github.com/mcneel/compute.rhino3d/blob/8.x/src/compute.geometry/GrasshopperDefinition.cs)

## Native acceptance

- Open both file formats through ordinary Slate placement. Verify a visible solid, curve, point, material, and hidden component against the same definition in Grasshopper.
- Edit each supported control, drag a slider rapidly, and verify the last value wins. Reopen the workbook and confirm that two viewers of the same definition retain independent overrides. Check undo, redo, source changes, and missing named controls.
- Compare the controls to the native Fillet and Fill palettes. Check that the value chip is clickable within the scrolling stack and that the color picker fits both a detached squircle palette and an attached blister.
- Open a palette and zoom and pan the canvas. Confirm that the host and palette track on the first frame of input, and that a scrollable menu still owns its wheel input while hovered. Check overlay icons over the model at both viewer sizes.
- Ask the Agent to create or revise a definition. Verify the linked source stays intact, the new `.ghx` appears in history, and opening it for a solve requires **Run definition**. For the chair, change all three sliders and the swatch, then verify the geometry and material in the preview and baked model.
- Use an owned package test fixture with a missing library. Verify automatic restoration, exact component identity on reopen, an existing compatible installation, and a clear failure for an unresolved package.
- Bake three revisions. Reopen each `.3dm` in the ordinary Slate 3D viewer and verify its geometry, units, and available material and layer attributes. Check placement beside the source and below the prior bake, including after undo, redo, and workbook reload.
- Record native frame pacing during solves and package restoration. Verify that pan and zoom remain responsive, old completions cannot update a different viewer, and failures preserve the last successful preview and prior bakes.

## Validation to date

- The Rhino 8 mailbox fixture ran eight jobs with all 57 installed Grasshopper libraries loaded. `.gh` and `.ghx` opened headlessly, and source hashes stayed unchanged. The test changed all five editable control types, preserved independent viewers, restored defaults, and kept stable choice IDs across a reordered list.
- The fixture reopened the preview and baked files, checked native curve, Brep, and point geometry, excluded a hidden point, and verified that changes to the slider and Custom Preview material reached the baked model. With the installed libraries, the first result took 75.5 seconds, warm solves 171–294 ms, and warm bakes 327–879 ms.
- The package planner and local archive flow passed seven focused Rust tests. Live Yak discovery resolved a public package GUID and filtered a fixture to compatible Windows and Rhino versions. Yak installed a local test package into an isolated scratch folder. The live Slate workflow exercised the local `.gha` route. An automatic network install and restart against a user profile remain open.
- The initial helper stalled while loading the installed libraries. Loading Rhino Commands and Rhino Scripting before Grasshopper reproduced McNeel Compute's startup order and cleared the stall on the test machine. The helper starts with the existing user plug-in profile. [McNeel Compute startup](https://github.com/mcneel/compute.rhino3d/blob/8.x/src/compute.geometry/Startup.cs)
- Slate’s Rust parser loaded all three preview proxies from the fixture. The native evaluation build opened the definition, updated the preview after a Width change, and stacked two baked cards. Reopening the workbook in a second evaluation build restored Width `9.404` and both baked cards. Arbitrary plug-in drawing that exposes neither geometry nor a bake path is reported as an omission. The `.3dm` bake retains analytic curves and points. Slate’s ordinary `.3dm` renderer currently displays the cached surface meshes of the baked card.
- The native `.gh` drop fixture initially showed **Drop plug-ins**. Dragging both test `.gha` files from Slate's Windows file picker onto the viewer solved the definition and enabled Bake. Slate kept one linked file on the board and recorded one verified component for each plug-in. The test approval records were removed after verification.
- The native chair workbook showed progress on both viewer sizes before Rhino finished loading. The large palette remained attached at 100% and 112% canvas zoom. A live Codex turn submitted from the Agent palette renamed **Chair width** to **Chair width (mm)**, saved a separate revision, and reported token usage. Slate opened the revised chair after **Run definition** and displayed the new control name. The original archive hash was unchanged. The reference chair’s embedded C# also passed Rhino solve and Bake with all three sliders and the color control changed.
- The [linked pavilion workbook](examples/linked-grasshopper/README.md) has five real Rhino 8 definitions and ten typed Slate connections. The headless helper produced the pavilion preview from the fan-out and fan-in graph. It retained populated item, list, and tree data, rejected invalid inputs, and reloaded a saved definition in the warm worker and after closing the viewer. A seeded 32-case run also confirmed that Rhino itself omits empty branches in some Number getter solutions.
