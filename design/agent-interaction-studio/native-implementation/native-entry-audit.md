## Concrete current causes

1. **Model entry/catalog mismatch:** starter uses pending Image/Text kind and cross-engine `agent_models`, whereas the repaired Chat catalog branch requires an already stored `PortalView::Chat` agent. `runtime/models.rs:100` formats image entries as model name plus `· API key` / `· add API key`; those combined labels are passed into the Model detail. This explains the kind of Sunburst image/API label visible in the rejected model UI. A native model editor needs the actual modeling runtime/capability owner, not an image fallback or a disguised choice that creates a separate chat surface.
2. **Pending versus bound data mismatch:** `generator_chrome_data` gets provider/model/parameters/access from stored agent data, not starter draft selection. `dispatch_generator_provider` eventually calls `set_flow_model`; that function patches only an existing agent and otherwise merely remembers a default. It cannot configure an unbound original source. A shared pending-context adapter must supply consistent catalog, selected provider/model, parameter metadata and explicit submission intent without mutating the source in paint.
3. **Common picker presentation:** `generator_chrome.rs:35` supplies provider icons as None. `generator_picker/rows.rs:45` starts with no icon and gives Model its icon; unsupported Effort/Speed remain iconless. `menu_selector.rs:430` changes label inset from8 to30 per row based on icon presence. Detail text is right-aligned in a clipped region without an ellipsis, so long combined values can lose their leading text. These are common owner gaps, not grounds for one renderer per modality. JS `chat-train/agent-picker.js:34` reserves the glyph column for every row and provides field icons.
4. **Credentials are not wholly absent:** the shared Provider secondary branch already exposes Add/Change API key (`generator_picker/rows.rs:159`), backed by cached `PackSession::credential_present` and explicit existing key-entry dispatch. A key hint attached to a model label is not that action. The ordinary first-use path must actually reach the correct provider ID/credential action without changing a draft into a key composer. No secret probes or saves belong in paint.
5. **Legacy model-only action:** `model_chat_starter_extra_height` plus `editor_helpers.rs:223` reserves a full extra row and paints the old `portal_action_button`; it dispatches `portal.agent.spawn` with kind `agent`. That command creates an ordinary separate local Chat Train wired to the source (`board_flow.rs:330`), not an in-place modeling binding or native grant. Its prior existence does not establish parity with the reviewed JS reference.

## Actual capability criteria and preservation boundaries

- Catalogs must come from the installed/discovered runtime and actual model metadata; selected opaque model IDs remain validated by `agent_set_model`/the applicable submission owner. Shared display labels or `PortalView::Chat` alone are not proof of native tool authority.
- Current native attached-model path (`agent_presence/chat_train/attached.rs:12`) requires Image host, provider **codex**, Chat view, current tail and `headless_model_agent_context`. Bound worker/source/document identity, accepted source revision, scope, read-only/denials, leases and explicit Board access/Resume remain authoritative. Do not claim another advertised Chat/text/image provider can operate that channel without its existing implementation.
- Dashboard artifact submission uses existing `linear_provider` (**codex/cursor**); plain Text supports its existing `TEXT_ENGINES` (**ollama/codex-text/openai-text**); Images supports its actual image engines/catalogs. Preserve those capabilities rather than applying a new universal provider allowlist. Chat Train must retain its actual supported installed programs and catalog validation.
- Opening an editor/menu must not bind a session, create a child, launch a host, grant access, write source, resize imported geometry or start inference. Any source binding belongs to an explicit authorized configuration/Send operation using existing journal/binding owners. A temporary program-bound node may prepare the agent reference, but only that reference should attach to the original host; preserve item/source, rect, style, rotation, text, model camera/view, native identity, drafts and prior outputs. Do not call a portal-oriented binder directly on imported media if it converts/resizes the host.
- Preserve original-source Unicode passage snapshots, ordinary non-query output/spawn lifecycle, source-write guards, active/inactive result identity, graft/history cuts, immutable Chat rails, cancellation/Undo and existing global preference versus native Board authority separation. No auto-grant, hidden Resume, self-wire, credential-in-document or new permission controller.
