# Native Studio implementation — shared-owner gate

Date: 30 October 2026. Reviewer: DRY / Article XII. Scope: read-only audit of the current working tree; no Rust edits or builds were performed.

**Verdict:** extract-first

**Why:** The native tree already has a capability-neutral generator, model-parameter picker, output-history renderer, image surface/blister owner, result-selection controller, wire semantics and timed panel memory. A separate Rust UI implementation for each Studio tab would violate Articles X and XII.1/XII.4. Extend these owners once, then supply provider/content adapters. Preserve the two native/export interpreters and P2.PortalHost. The initiative is approved in principle after the narrow shared API/extraction prerequisites below; this is not permission to copy a complete image/editor/portal implementation into each modality.

## First-wave file ownership

The parent has protected the dirty baseline at `target/studio-native-baseline/20261030-204228`. Work must be compared against that baseline, not against HEAD alone: 133 modified tracked files and 205 untracked files already contain independent work. No builder should stage/revert those files wholesale.

1. **Shared chrome builder:** exclusive ownership of `crates/atlas-shell/src/selection_tools/generator*.rs`, `agent_image*.rs`, `menu_selector*.rs`, `prompt_fields.rs`, and the result-strip presentation changes in `home/album_strip.rs` / `result_actions.rs`. Publish the revised structs/response intents before app adapters change call sites. Keep the shell free of `slate-doc`, app or provider dependencies. Existing `home.rs` reexports should be touched only by this builder or the integrator.
2. **Image/history app builder:** after the shared signature is agreed, own `apps/slate/src/app/board_flow/{image_editor,editor_helpers,image_workflow,result_actions,ports}.rs` and their child tests plus `board_agent/{picture,generator,generator_pump,chat_edge}.rs` only when explicitly assigned. It consumes the shell API; no local picker, transcript, menu-row or blister implementation. Coordinate any `board_flow.rs` / `board_agent.rs` module declarations through the integrator.
3. **Text answer builder:** own the new pure annotation helper under `crates/slate-doc/src/` and its tests, then `board_flow/text_note.rs`, `board_agent/interactive_text.rs`, and the corresponding export consumption. `scene.rs`, `slate-doc/src/lib.rs`, `atlas-shell/src/canvas_text.rs` and `slate-artifact/src/render.rs` are integration locks, not files multiple builders may edit concurrently. A schema patch must include existing constructor compatibility and serde defaults. This work can run alongside shell implementation once its data API is agreed; it cannot independently add a second transcript/composer.
4. **Integrator/shared-data owner:** retain exclusive control of `apps/slate/src/app/{mod.rs,board.rs,board_agent.rs,board_flow.rs,commands.rs}`, command registry additions, `crates/slate-doc/src/{scene.rs,lib.rs,agent_inputs.rs,wire_host.rs}`, and any `Cargo.toml`/lock changes. Graft job planning and generator memory metadata must be designed once here, or explicitly assigned as an atomic handoff to one worker. Parallel image/history edits must not race with this owner.

Dashboard and Rhino UI adapters should be the next wave after shared chrome is stable, rather than two more concurrent copies of the image adapter. Builder reports must name exact changed files, the shared functions called, new persistent fields, tests and any unimplemented acceptance points.

## Smallest prerequisites before execution

- Reconcile current constants through their existing owner rather than overriding them in adapters: native generator inset is 12 (`generator_layout::INSET`) versus the reviewed compact 8-unit prompt/16-unit dialogue insets; native result circles are 26 versus Studio 18; the album index strip is currently 22-unit squares, 5-unit gaps and a single window of at most 24 versus the reviewed 24-unit squares, 4-unit fillets/gaps and eight-column running bond. Native typed-port top is 30 (`wire_host::FLOW_PORT_TOP`) while Studio input centers start at 48. Changing presentation must not rewrite durable `InputPort::t`/slot identity or reconnect saved wires incorrectly.
- Record the final shared data contract: header slots, provider/key action, supported parameter rows, persistent-history toggle, prompt/transcript view, result thumbnail source, and returned intents. Remove divergence in `generator_editor` versus `image_agent_editor` through one shared compact datum API.
- Decide the app boundary for a common conversation view. Reuse shell fold/follow primitives and extract presentation-only pieces from the Chat Train adapter; do not pass `Node`, `AgentSession` or provider clients into the shell. Existing approval/result/error views remain functional even when their usual appearance changes.
- Identify a generic result reference/thumbnail provider that can wrap image results, artifact revisions and model/text output. Preserve the existing image result identity/selection controller and asynchronous caches. `thumb: None` must not be disguised as a final thumbnail implementation.
- Settle one journaled document representation for graft settings, generator history endpoints and text answer anchors before workers add fields to scene structures. The graft planner is a pure input-snapshot transformation; bounded provider scheduling remains outside the renderer.
- Keep all source/connection changes reversible through existing scene commands and journal paths. Fewer prompts does not remove request-scoped authorization, read-only state, explicit source-writeback, or cancellation safety.

## Headless Rhino steering

The existing connector protocol already has `SurfaceMode::Headless` in `crates/atlas-connector/src/model.rs`. Therefore the new requirement does **not** justify inventing another host protocol or viewport. Extend the existing connector operation/admission/result path (`atlas-connector`, `atlas-connector-runtime`, app `application_connector` worker/native adapter) with a registered headless Rhino engine capability. `CommandEffect::{DraftMutation,SourceWriteBack}` and `UndoOwner` remain authoritative. Completed outputs pass through the existing artifact receipt/transfer/provenance path, then the existing `.3dm` preview pipeline.

The audit found a registered `org.slate.rhino-inside` pack and generic connector implementation, but did not find an actual `RhinoCore` / `RhinoDoc.CreateHeadless` engine implementation in the inspected source. `SurfaceMode::Headless` and a mock are protocol support, not proof of working Rhino execution. A real adapter must verify installation/license and host API behavior; it must not pretend to succeed with a projected demo. Run it as a dedicated worker with no document window. Keep the existing interactive Rhino connector as an optional separate mode, with its current ownership/dirty-detach semantics.

Do not add a new `board_rhino.rs`, duplicate `model3d.rs`, embed an external Rhino viewport for the headless path, start model work on the paint thread, or let an agent's generated script bypass the declared operation/admission boundary. Required new dependency/runtime decisions must be reviewed before altering build configuration.

## Twins that would otherwise grow

- `generator.rs::generator_editor` / `agent_image.rs::image_agent_editor`: two independent header geometries. Replace with one compact measured datum, retaining image-specific data hooks.
- `portal_bound.rs::paint_agent_bound` / `generator_body.rs` / `generator_activity.rs`: parallel conversation/follow/scroll/composer styling. Extract shared presentation, retain separate data/session routing.
- `ArtifactHistory::get` plus a proposed Dashboard/3D/Text selector: existing `GeneratorHistory` already accepts thumbnail IDs. Supply data rather than add widgets.
- `home/album_strip.rs` plus five new hover-strip renderers: extend existing square-layout/hit logic and result controller, with scoped generator policy rather than breaking Cover Flow.
- `selection.rs` plus per-tool rebound timers: keep the existing 1500 ms memory owner and `GeneratorPresentation`.
- `wire_host.rs` / `agent_inputs` plus per-tool graft matching, offsets or duplicated memory state: one durable semantic/geometry source; source-content adapters can differ.
- Existing `.3dm` loader/scene plus new Rhino geometry render state: use the existing model-preview pipeline.

## Review and regression gates

- Shared geometry tests exercise small/medium/large/empty/attached/detached states, long model names, fixed/unsupported parameters, and matching paint/hit rectangles.
- Keep Chat Train fold, authored-width/height retention, follow-scroll, direct-manipulation and immutable checkpoint tests; extend them rather than replace with new happy-path tests.
- Extend existing generator picker/attached/activity, image surface/geometry, result held-hover/expanded/save, wire rail/input compatibility and connector admission/cancellation tests.
- Browser/native visual comparison must use the same viewport, zoom, selection and editor state; screenshots alone do not prove hover bridges or 1500 ms timing.
- Artifact source/history/export, ordinary album navigation, image editing tools, pending-output recovery, provider catalog loading, API-key renewal, read-only behavior, connector permissions and cancellation are explicit preservation checks.
- A shared change is integrated once. Any new duplicate requires a named owner/extraction plan or an explicit temporary `docs/audit/deviations.md` row; no silent exception.

## Deviations

DV-18 (locator wrappers) and DV-20 (shared bake/focus/empty paths) are recorded closed by the existing source audit: retain those owners. DV-19 (File Atlas scan/watcher duplication) remains open and is outside this initiative. Do not expand it through the agent work. No new duplication deviation is approved by this gate.

Final gate: **extract-first** until the shared API and integration locks above are assigned. After that, the scoped first-wave work may proceed without creating new per-modality chrome owners.
