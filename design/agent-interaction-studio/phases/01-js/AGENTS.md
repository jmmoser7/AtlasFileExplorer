# 01 — JavaScript Studio

Purpose: refine one existing element through concrete browser interactions.
This is the current self-contained HTML/JavaScript/CSS Studio; read
[shared rules](../../AGENTS.md) and the selected element's current contract.

## Keep the loop light

- Edit the affected element's HTML, JS, CSS and focused fixtures. Reuse shared
  picker, dialogue, navigation and state owners instead of copying them.
- Keep Studio controls outside the element. Preserve existing capabilities
  and approved behavior; use reversible interactions and labelled simulations.
- Read native source/captures as references. Do not modify or build Rust or
  require a compiled service merely to preview a browser iteration.
- Keep dependencies minimal and reload the static page after changes. The
  home and phase shell remain static; opening a Rust stage starts no build.
- Record proposals separately from agreements. Only explicit approved
  decisions update the contract/decisions owner; a successful preview is not
  approval or native acceptance.

## Cheapest valid checks

- Run relevant existing JS syntax/state checks and inspect the changed browser
  flow at representative viewport, theme and canvas zoom.
- Exercise changed gestures, menus, dismissal and persistence as applicable;
  keep the original assertion intent. No Rust build or blanket workspace suite.
- Identify simulated replies, credentials and provider/runtime availability.
  Do not call browser pixels proof of production geometry or execution.

## Handoff

- Preserve source revision, fixtures, captures, entry actions and observed
  results, including failures and untested states.
- Keep the standalone element contract current with approved behavior,
  constants, real production owners and remaining questions.
- Hand approved references to authorized Rust work when needed. Component and
  native ordinary-entry evidence remain separate required claims.
