## Implemented source and owners

Shared Cover Flow remains `atlas-shell::home`; there is no copied rack engine.

Membership, positions, grants and jobs are never restored from those files.
- Human direct messages: the UI-free `atlas-relay` owner uses authenticated encrypted rooms with ephemeral membership and pinned certificates. Acceptance is distinct from delivery. The recipient's actual durable save precedes Ack; failed saves never Ack. Reconnection/retry preserves message identity and text, without automatic resend. Contacts retain bounded portraits independently of room membership. This slice shares no board scene or source files.
- Canvas presence: the same camera zoom applies to face, calibrated hat, activity prop, name and farewell. A moving avatar is held on the first press; double-click routes the registered address command, pauses board work, shows listening and attaches recent conversation beneath its sampled position. Closing conversation leaves it paused until Resume. Foreground panels, dismissal clicks and avatar clicks are intercepted before board hit testing.
- Appearance: the approved eye-only rig, independent180ms expression/475ms gaze channels, nine directions and26 fitted hats plus none. Neutral fits are the canonical shared asset; hats follow the sampled head pose. Straps remain removed. The user retains final judgment of fidelity at actual marble size.
- Harness handoff: same-harness no-op, destination validation, after-task/stop-and-switch/cancel choices, explicit visible history checkpoint, typed separate bindings, model catalogs and request-specific cancellation. Helpers, reads, generated image jobs and pending proposals count toward task completion. No automatic resend or copied provider Full access.
- Low-overhead activity: the existing public-event/call reducer maps the33 canonical classes to eye/gaze/prop states, including an animated reading book. It does not require a separate model state announcement or private reasoning. Coarse inference must remain visibly coarse.
- Visible board workflows: existing journaled targeted move/resize/order/frame/text/shape/wire/delete commands retain witnessed sequential motion and proposal/autonomy checks. New `create_train`, `create_generator` and `place_images` reuse pure preparation extracted inside existing flow/media owners. Creation neither starts a provider nor creates directories or grants authority. Applied replies return stable created IDs. Source metadata is rechecked before commit, including staged creation acceptance.
- Useful reads: bounded scoped descriptors expose item names, IDs and permitted program/conversation metadata. Explicit `presence.read_image` reuses the existing asynchronous input pool and composition owner; file-input consent, cloud-placeholder refusal, request/generation fencing and live grant rechecks apply. No whole-board image attachment or bulk cloud download.
- Parallel conversations: existing relay and message owners remain in charge. An explicit human option allows only chats this live agent creates to become its endpoints after commit. It defaults off, excludes unrelated chats and does not confer file inputs, autonomous edits or Full access. Relay submission preserves a human's existing composer, caret and selection through immediate/deferred success or failure.
- Temporary helpers: canonical join enforces capacity and bounded parent scope. Helpers have visible parent identities, return results and participate in transitive cancellation/completion. The permission to manage newly created chats is not inherited. Expiry/retirement fences their old request authority. A helper that emits progress and later fails still needs corrected outcome provenance; that repair is in progress and has no completed-test or successful-handoff claim.
- Retirement/restore: existing bow/puff, sunset, edge and real-portal/fallback departure owner; authority is revoked before the visual farewell. Advanced can restore identity/history with fresh membership and explicit new authority.
- Scheduling: shared compact dialog, explicit bounded end, existing cadence parser. Config may persist, but live jobs and authority do not. Runs require a freshly armed live board/grant, wait for busy/paused work, avoid overlaps and skip missed/inactive intervals. This is not an unattended OS scheduler that revives retired agents.

## Explicit boundaries

Generated images must already be registered through the existing output/import owner before targeted placement; arbitrary source paths are refused. Placement into a tagged frame requires the item already to have the frame's assignments. A scene-only proposal cannot silently mutate item tags outside their journal. Untagged presentation frames remain supported.

Independent destination moves are separate BoardCalls: each real displayed node animates continuously before its call journals. A multi-ID relative move is one atomic command; its non-frame targets currently animate sequentially and commit together. Stop or conflict discards that command's uncommitted previews, so earlier visible placements within the group revert. Frames carry their children together. This does not establish per-target durable commits inside an atomic group, and native multi-frame observation remains pending.

Real providers still require the user's existing setup and permissions. A local Dot connection is the existing scoped file-link protocol, not a fabricated built-in Dot service. Human messaging is not multiplayer board synchronization. All these boundaries must appear in acceptance results when a requested workflow cannot run.

## Why the earlier integration missed the design

The earlier verification exercised backend plumbing and the closed roster, while the failing workflows were the open profile/conversation, composer, controls and zoomed canvas avatar. The native implementation also retained the activity inspector and hard-coded identity instead of translating the accepted conversation design. Those missing acceptance paths explain how a promising prototype became an unusable final UI. This batch keeps original-request criteria, shared implementation ownership, independent intent review, automated evidence, native observations and user acceptance distinct.

The initial83d native review exposed a second concrete translation failure: default proportional text resolved to Ubuntu Light, primary conversation text used the faint global secondary color, and the scaled conversation retained a screen-coordinate Area clip. The repair supplies the existing registered regular face as presentation data, resolves stronger presence-only muted text from theme slots, and inverse-transforms the viewport constraint for painting and input. Five focused regressions cover real composer/send interaction, offscreen rejection, typography fallback and isolation, and world-label scale. Independent source review found no P1/P2 in this repair, and those five regressions passed in both the historical 375-pass snapshot and the latest shared suite. This scoped success does not verify the newly corrected transcript or final full-app appearance. Approved hat calibration, header transparency and dimensions remain intact.

The intent guardian subsequently identified missing accepted content gutters and explicit multiline leading in populated conversations. The existing transcript owner now restores the 16/14 px desktop/attached content gutters, 18×14/13×10 px bubble padding, explicit 1.35/1.45 leading, accepted row spacing and symmetric outgoing anchoring. Scoped formatting and diff checks passed, and the source correction was independently approved (`target/presence-transcript-metrics-source.json`). Its real egui incoming/outgoing desktop/attached regression remains pending; the combined attached enclosure/content inset also needs native visual comparison. This restores the accepted metrics without revising the design or assigning a native/user pass.
