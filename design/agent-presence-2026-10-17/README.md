# Participant conversation redesign

Status: revision2 accepted by the user on17 October2026; native implementation and verification in progress. Supplied images are preserved beside this file. `metrics.json` owns the accepted geometry. Design acceptance does not establish that the native implementation passes its checks.

The earlier native UI opened an activity inspector instead of a conversation with a composer, hard-coded the human identity and replaced conversation bindings on rejoin. Passing plumbing tests and inspecting the closed roster did not validate those missing flows. The earlier Windows computer-use helper failed, so native click-through was never completed; it should not have been treated as acceptance. This integration adds a separate durable conversation/profile owner and preserves fresh ephemeral membership and grants. Its native acceptance must be recorded separately.

The new reference is conversation-first: one segmented participant capsule, separate icon/chat and name/profile targets, simple persistent name/photo, message bubbles, compact agent controls, a visual hat picker, and a board avatar that scales with the camera and pauses to listen on double-click.

## Review scope

`prototype.html` is an interactive design review using the approved face engine. Conversation data is sample/local browser data. Provider actions are simulations; no message is sent to Codex, another person, or another agent. The reference pictures are evidence, never substituted for working controls.

Required review states: self profile, self chat, agent chat with history and composer, overflow, scrolling hats, long names and multiple participants, 720px height, narrow viewport, 25/100/200% world scale, and double-click while moving. The below-avatar chat follows the canvas; roster-open chat is window chrome. Revision2 adds one enclosing conversation surface, gentle retirement, canonical Cursor/Codex glyphs, and simulated harness-switch timing. All26 user-calibrated neutral hat fits are consumed directly.

`cover-flow-preview.json` is generated by the existing shared renderer example: `cargo run --locked --release -p atlas-shell --example cover_flow -- --export-hat-poses design/agent-presence-2026-10-17/cover-flow-preview.json`. It samples the actual rack owner; the browser only interpolates poses. Browser scroll/snap motion remains approximate. `provider-icons.json` selects the two existing canonical glyphs from the shared tool-icon inventory. Native integration must call or extend `atlas-shell::home::image_album` and use the canonical icon inventory directly.

## Implementation ownership after agreement

- `atlas-shell::agent_presence`: unified roster, conversation chrome/bubbles/composer, profile and hat presentations; apps supply data/actions.
- Slate `agent_presence`: route avatar/name actions, pause/listening lifecycle, camera transform, profile persistence and conversation binding.
- Existing `atlas-agent::AgentSession` and `atlas-ai::AgentSources`: persistent provider history. Keep durable conversation identity separate from fresh ephemeral membership and grants (Constitution VIII.5).
- Other-human delivery needs a real transport. The current `atlas-session` bridge only links Slate to File Atlas; it is not multiplayer messaging. The UI must not report remote delivery before a transport confirms it.

The user explicitly accepted the design checkpoint and instructed full native integration. `NATIVE-BUILD-PLAN.md` records the ownership, required transport dependencies and validation scope. The new encrypted human-message relay is independent of board synchronization; a room grants no board or provider authority.
