# Application connector v0.2 candidate

v0.2 retains the v0.1 wire shapes and authenticated transport, and negotiates an exact version intersection. It adds host-local, revocable authority for agent commands on explicitly isolated native drafts. Existing v0.1 sessions retain inspection-only agent command admission.

A trusted host may call `Session::grant_draft_authority(grant_id, agent_id, source_scope, command_ids)` only after explicit user authorization. The binding must be `isolated_draft`; the source revision is checked at grant creation; native document identity, source identity, agent and closed command IDs remain pinned as revisions advance. Grants are bounded, session-local, absent from serialization, cleared on source transitions, detach and reconnect, and independently revocable. An agent also needs workspace autonomy and an eligible advertised command. A connector descriptor never creates a grant. Revocation blocks future admission and does not assert rollback of an already admitted native effect.

Eligible v0.2 ephemeral view commands may run for agents without source edits. Source write-back remains human-only, with per-action direction naming the exact target. No grant authorizes a linked original, arbitrary code, a new executable, or implicit save/discard. The Rhino adapter independently enforces version, draft mode, autonomy, its static command whitelist and approved roots.

Machine registrations live under `%LOCALAPPDATA%/NativeFileAtlas/application-connectors/{registration}.json`. Fields are `executable` (existing absolute path), `arguments` (bounded argument-prefix array), and `approved_roots` (existing absolute directories). Reserved rendezvous/root arguments cannot be overridden. The launcher creates only the selected executable suspended, binds a current-user-only pipe against its independently known PID, then resumes it with `--slate-token`, `--slate-pid`, and the selected approved `--source-root`. Dropping a successful launch does not terminate Rhino. A never-resumed helper may be terminated on launch setup failure only.

Native capture provenance uses the pure `capture_xmp` / `parse_capture_xmp` envelope with namespace `https://slate.app/ns/connector-capture/1.0/`. Bounded native JSON is hex encoded in XMP. It preserves source/revision, native schema/version/fidelity/state, UTC timestamp, dimensions and consistency; it never coerces a native parallel or two-point view into Slate's perspective camera. Parsing metadata does not grant restoration or source authority.

See [v0.1 framing and transport](../v0.1/README.md), [joint handoff](../HANDOFF.md), and [model portal contract](../../keymap/contracts/portal-application-connector.md). Native Rhino acceptance remains pending.

## Durable camera bookmarks

A Slate native still may add the independently observed SHA-256 and byte length of its already selected linked source only while its clean native state still represents that initially bound file. A changed native draft or dirty document must not inherit the original file fingerprint; publish and rebind a saved draft before producing a durable bookmark for that file. `view_for_restore` retains exact scope matching within a live session. Across a reconnect or moved identical file, it returns a view for the current bound scope only after the host independently verifies identical content; the original captured source/revision remains in the unchanged image metadata and in restore-origin provenance. A metadata path never selects or opens a file. Missing or mismatched fingerprints refuse this compatibility path. Ordinary human authority, schema and units checks remain mandatory; poster-only views cannot restore a camera.
