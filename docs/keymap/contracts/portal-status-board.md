Command: `board.portal.status_board` (placement) · Key: none (P1.portal / OQ3

Inherits: P0.* (all), P1.node, **P1.portal**, **P2.DragShape** — deviations

## What it is, and the 10% it implements

A journaled frame on the board whose contents are one **authored status
snapshot** (`project-state.json`): roadmap and workplan scores, open
deviations, and the next critical actions. The real use (Art. III): reading
where the project is *on the board next to the drawings it describes*, so a
slide or a working canvas can carry the same numbers the handoff dashboard
already computed.

The 90% deliberately not implemented is in D15: this is not a live git or CI
client, not an editor of the snapshot, and not a second tab-level `ViewKind`.

## Pushback before agreement (Art. XI)

The request was to "turn this into a portal." Two clauses bind that:

1. **Article V.3 — generated portal.** The dashboard HTML is a disposable
   interpreter. The portal is a journaled frame (`rect`, `source`, `query`);
   the painted bands are derived and never stored on the node. Shipping the
   HTML file as a host portal would make the board a browser, which is Wave 5
   and the wrong class for a file we already own.
2. **Article I.4 / IX.2 — no author's machine in the kit.** The recipe names
   no `source`. Binding is a human step after placement. A kit that shipped
   `docs/status-dashboard/project-state.json` would only resolve on this
   checkout.

Neither point reduces the requested view — the same snapshot, on the board,
regenerated by both interpreters from one layout function (Art. IV).

## The extracted model

Pure crate `crates/status-board`, no renderer and no app dependency
(Art. I.1), Linux-testable (Art. I.3): `load.rs` (path → `Snapshot`),
`layout.rs` (`Snapshot` + `StatusQuery` + frame size → `StatusLayout`),
`model.rs` (frozen types + `fingerprint()`).

## Golden paths

- **GP1 (place, unbound):** palette "status board" · click → one portal
  node, `source: None`, empty state painted, tool = Select, one undo step;
  scene JSON contains the frame and the default query and **no** contents.
- **GP2 (bind):** select the portal · `portal.status.source` → fixture
  `project-state.json` → one `Patch`; after the pump, caption contains the
  fixture HEAD and layout prims are non-empty.
- **GP3 (undo is frame-only):** GP2 · Ctrl+Z → source back to `None`, no
  orphan nodes, no journal entry mentioning a score.
- **GP4 (determinism):** two portals, same source, same query, same frame
  size → identical `status_board::fingerprint`.
- **GP5 (missing source):** GP2 · rename the fixture · refresh → state
  `Missing`, locator named, frame and query intact.
- **GP6 (export parity):** GP2 · export → the artifact contains the
  caption / KPI text from the same layout function; unbound exports a
  state card.
- **GP7 (bake):** GP2 · `portal.status.bake` → one undo step adds authored
  nodes; the portal still exists and is still live.
